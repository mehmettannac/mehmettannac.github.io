Django'yu bir mimar gibi düşünmek: MVT yapısıThinking about Django like an architect: the MVT pattern

Model, View ve Template katmanlarını restorasyon eğitimimden aldığım bir bina benzetmesiyle anlatıyorum.Explaining Model, View and Template with a building analogy from my restoration training.

Mehmet Annac~4 dk~4 min

Django, Python ile web uygulaması yazmak için kullanılan bir framework. Öğrenirken yapısını kafamda en iyi oturtan şey, restorasyon eğitimimden kalan bir alışkanlık oldu: her şeyi bir bina gibi düşünmek.

MVT: Model, View, Template

  • Model = statik proje. Binanın taşıyıcı sistemi gibi; verinin nasıl saklanacağını tanımlar.
  • View = sirkülasyon. Ziyaretçi bir kapıdan (URL) girince hangi odaya yönleneceğine, neyi göreceğine karar verir.
  • Template = cephe. İçerideki verinin dışarıdan nasıl görüneceğini belirleyen HTML.

Model: projelerimi saklamak

Örneğin bu sitenin Projeler sayfası Django ile yapılsaydı, her proje için böyle bir model yeterdi:

from django.db import models

class Proje(models.Model):
    baslik   = models.CharField(max_length=100)
    teknik   = models.CharField(max_length=50)   # Layer Mask, Smart Object...
    puan     = models.PositiveSmallIntegerField()
    gorsel   = models.ImageField(upload_to="projeler/")
    eklendi  = models.DateField(auto_now_add=True)

View ve Template

View veriyi veritabanından alıp template'e veriyor, template de onu HTML'e döküyor:

# views.py
def projeler(request):
    liste = Proje.objects.order_by("-puan")
    return render(request, "projeler.html", {"projeler": liste})

<!-- projeler.html -->
{% for p in projeler %}
  <h3>{{ p.baslik }}</h3> <span>{{ p.teknik }}</span>
{% endfor %}

Neden seviyorum?

Django'nun hazır gelen yönetim paneli sayesinde, kod yazmadan bile içerik ekleyip silebiliyorsun. Bir binanın planını bir kez doğru çizince içini rahatça döşemek gibi.

Django is a framework for building web applications with Python. What helped me understand its structure was a habit from my restoration training: thinking about everything as a building.

MVT: Model, View, Template

  • Model = the structural plan. Like a building's load-bearing system, it defines how data is stored.
  • View = circulation. When a visitor enters through a door (a URL), it decides which room they go to and what they see.
  • Template = the façade. The HTML that decides how the data inside looks from the outside.

Model: storing my projects

For example, if this site's Projects page were built with Django, a model like this would be enough for each project:

from django.db import models

class Proje(models.Model):
    baslik   = models.CharField(max_length=100)
    teknik   = models.CharField(max_length=50)   # Layer Mask, Smart Object...
    puan     = models.PositiveSmallIntegerField()
    gorsel   = models.ImageField(upload_to="projeler/")
    eklendi  = models.DateField(auto_now_add=True)

View and Template

The view gets the data from the database and hands it to the template, which turns it into HTML:

# views.py
def projeler(request):
    liste = Proje.objects.order_by("-puan")
    return render(request, "projeler.html", {"projeler": liste})

<!-- projeler.html -->
{% for p in projeler %}
  <h3>{{ p.baslik }}</h3> <span>{{ p.teknik }}</span>
{% endfor %}

Why I like it

Thanks to Django's built-in admin panel, you can add and remove content without writing any code. It's like furnishing a building comfortably once its plan has been drawn right.
